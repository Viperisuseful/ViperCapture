# ViperCapture OSS 0.2.0-beta.4 Developer Beta

This beta makes the HTTP API more predictable and safer to integrate. Request
correlation now uses `X-Request-Id`, while retry deduplication uses the standard
`Idempotency-Key` header for single and bulk async jobs. Existing SQLite job
databases migrate safely, queued payloads remain encrypted, and legacy retry
keys retain a compatibility path.

Authentication failures now advertise Bearer authentication correctly. Rate
limit responses report a truthful sliding-window `Retry-After`, baseline PUTs
return 201 with `Location` when creating and 200 when replacing, and project
storage quotas are distinguished from oversized request bodies.

Bulk submissions now use HTTP 200 with explicit per-item statuses, canonical
request fingerprints, atomic request-level idempotency, and isolated internal
key namespaces. Metrics are protected by default when the control plane is
enabled, while health and readiness endpoints remain available to
infrastructure. Compatibility query-string authentication stays isolated to
`/take` and can be disabled by operators.

The Python and TypeScript SDK versions advance with the API contract.

## Release evidence

- 452 Python API, persistence, security, compatibility, and renderer tests;
- CodeQL analysis for Actions, Go, JavaScript/TypeScript, Python, and Rust;
- constrained-memory and sustained-load/recovery operational checks;
- web and renderer validation;
- checksummed source, SDK, Action, skill, integration, and Go bundles;
- versioned GHCR image built from the release commit.

## Beta boundaries

The API may still change before v1. Public operators remain responsible for
TLS, network egress, capacity, alert delivery, backups, upgrades, abuse
response, and support. The included deployment is a hardened starting point,
not a managed-service SLA.
