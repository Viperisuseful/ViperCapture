# ViperCapture OSS 0.2.0-beta.3 Developer Beta

This beta makes product-video output smoother and clearer. The web app now
lets you choose 24, 30, 50, or 60 FPS and a readable bitrate preset whenever
WebM or MP4 is selected. The renderer carries those settings through capture,
hardware encoding, software encoding, fallback, and final trimming instead of
silently falling back to low-quality defaults.

GPU mode now validates AMD AMF encoders with a compatible 128x128 probe frame
instead of the undersized frame that some drivers reject. It still falls back
safely to CPU encoding if the selected hardware path cannot render the video.

The desktop packages embed the same corrected renderer and are rebuilt as
0.2.2 for Windows, macOS Apple Silicon, macOS Intel, and Linux. The Android
native capture app remains independently versioned at 0.1.8.

The public documentation is also reorganized into a product-focused README,
quickstart, concepts, API reference, configuration, deployment, and
contributing guides without breaking existing help anchors.

## Release evidence

- full Python unit and renderer suite;
- React web and desktop lint/build checks;
- selected FPS and bitrate contract, transport, encoding, and fallback tests;
- real WebM and MP4 duration, frame-rate, bitrate, dimension, and motion probes;
- AMD, NVIDIA, Intel, Apple, Windows, and Linux hardware-encoder detection tests;
- packaged renderer smoke tests on Windows, macOS Apple Silicon, macOS Intel, and Linux;
- checksummed source, SDK, Action, skill, integration, and Go bundles;
- versioned GHCR image built from the release commit.

## Beta boundaries

The API may still change before v1. Public operators remain responsible for
TLS, network egress, capacity, alert delivery, backups, upgrades, abuse
response, and support. The included deployment is a hardened starting point,
not a managed-service SLA.
