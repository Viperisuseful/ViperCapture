# ViperCapture OSS 0.3.0-beta.1 Developer Beta

This beta adds operator-controlled browser access features for self-hosted
deployments. Each render can use an HTTP, HTTPS, SOCKS4, or SOCKS5 proxy with
separate credentials, while request-aware stealth defaults keep browser,
device, locale, platform, and user-agent signals aligned. Operators can disable
custom proxies globally, and hosted mode continues to reject them unless it is
explicitly opted in.

Portable session imports now accept Playwright storage state, common browser
cookie-export JSON, Netscape `cookies.txt`, and pasted Cookie headers. Imported
cookies, local storage, subdomain scope, empty values, and supported CHIPS
partition keys are normalized into encrypted project profiles; malformed or
oversized input fails with a stable validation error.

CAPTCHA handling remains detection-only. ViperCapture identifies common
blocking interstitials, distinguishes embedded widgets from page-blocking
challenges, and returns structured provider, kind, confidence, and signal data.
An operator may connect an approved external async handler, but this release
does not include a solver, credentials, token injection, or bypass service.

ViperCapture is now distributed only as the self-hosted web/API project and its
supporting source, container, SDK, Action, skill, and integration packages.

## Release evidence

- 479 Python API, persistence, security, compatibility, and renderer tests;
- real Chromium regressions for challenge detection and embedded widgets;
- CodeQL analysis for Actions, Go, JavaScript/TypeScript, and Python;
- constrained-memory and sustained-load/recovery operational checks;
- web and renderer validation;
- checksummed source, SDK, Action, skill, integration, and Go bundles;
- versioned GHCR image built from the release commit.

## Beta boundaries

The API may still change before v1. Stealth behavior and CAPTCHA detection are
heuristic and do not guarantee access to third-party sites. Operators are
responsible for authorization, proxy providers, handler integrations, network
egress, TLS, capacity, alert delivery, backups, upgrades, abuse response, and
support. The included deployment is a hardened starting point, not a managed
service SLA.
