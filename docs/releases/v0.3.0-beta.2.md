# ViperCapture OSS 0.3.0-beta.2 Developer Beta

This beta adds explicit browser-environment controls and stronger readiness
handling. Render requests can emulate screen or print media before navigation,
disable target-page JavaScript without disabling operator-approved actions, and
choose whether Chromium emits PDF structure tags.

Selector waits now support visible, attached, hidden, and detached states. The
optional image-readiness wait eagerly requests lazy images and covers open
shadow roots, child frames, dynamically attached frames, navigation, same-URL
reloads, and full-page lazy-loading passes within one bounded timeout.

The self-hosted workspace adds named capture presets, clearer advanced-control
grouping, system-theme defaults, and Windows renderer compatibility fixes.
Unused tabs source and its generated CSS were removed without changing the UI.

Site-access documentation now distinguishes caller-managed handoff from an
independent external challenge tool from ViperCapture's operator-installed
handler hook. ViperCapture does not bundle a solver, provider credentials,
token injection, or bypass service, and the documented authorization, origin,
SSRF, redirect, and egress boundaries remain in force.

## Release evidence

- 502 Python API, persistence, security, compatibility, and renderer tests;
- frontend lint and reproducible production build;
- real Chromium checks for media-at-load, disabled target JavaScript, and
  tagged PDF output;
- Linux and Windows web and renderer validation;
- CodeQL analysis for Actions, Go, JavaScript/TypeScript, and Python;
- constrained-memory and sustained-load/recovery operational checks;
- checksummed source, SDK, Action, skill, integration, and Go bundles;
- versioned GHCR image built from the release commit.

## Beta boundaries

The API may still change before v1. External challenge tools and operator
handlers do not guarantee access to third-party sites. Operators are
responsible for authorization, handler integrations, network egress, TLS,
capacity, alert delivery, backups, upgrades, abuse response, and support. The
included deployment is a hardened starting point, not a managed service SLA.
